## 800 token 总预算+字符系数标定

# 800 token 总预算 + 字符系数标定

## 铁律 / 契约

MUST：三个注入点（会话常驻索引、subagent 启动全文、显式取全文）的 token 总和 ≤800
MUST：预算口径用字符数 × 标定系数估算，系数按本库真实内容标定
MUST：系数往高估一侧取（倾向高估 token 数，低估会让实际开销超过 800）
MUST：新增注入点必须在 INJECTION_BUDGETS 表登记才能拿到预算（拿不到就报错）
MUST：压缩表达 + 降级低价值页，不截断（截断比超预算更危险）
禁：自行放宽预算口径或硬压到失效（若 800 内无法保留可照做的规则，应回报用户重定口径）
禁：用 tiktoken 或 API 计数（hook 热路径，tiktoken 对 Claude 是近似，每次往返不可接受）
禁：截断规则（会把规则从中间切断，得到读起来完整、实际缺胳膊少腿的注入）

## 反例 (命中=违规)

| 禁 | 改为 |
|---|---|
| 代码中硬编码预算值（PORT=8080 模式） | INJECTION_BUDGETS 单一数据表，CONFIG_DEFAULTS 回填 |
| 拍脑袋定系数（中文 1 字符/token） | 按本库真实内容标定，写在测试里可复算 |
| 为压进预算截断规则 | 压缩表达 + 降级低价值页（按价值密度而非单纯大小） |
| 预算超了只报"超了" | 给出可执行信息（还差多少 + 最大的几页是谁） |
| 用 tiktoken 计数 | 字符数 × 标定系数（零依赖、无开销） |
| 引入 tiktoken 或 API 计数 | 字符数 × 标定系数，标定过程留在测试里 |
| 压缩后放宽断言换绿 | 禁靠放宽断言换绿，既有语义断言是硬底线 |
| 以推断代替验证（AI 复读验法不可用时） | 如实标记为未验证，禁以推断代替 |

## 关联

测试接缝：三个注入命令的输出文本（最高接缝，越靠外部行为越好）
验收基准：既有测试逐条钉住不能丢的规则，压缩后必须原样绿
