## flow 文档禁假设分工下沉

### 触发场景
- 执行分工变更（如 exec/check/finish 从 main 下沉给 agent）
- 涉及 flow 文档 + skills/references + agent.md 多处改动
- 不同层级同时维护相关内容

### 陷阱-正解
**陷阱**：flow 文档描述"main 负责 X 动作"，但实际代码已下沉给 agent 自跑（或反之）— 导致 main 与 agent 双跑或双不跑。

**正解**：载体分工变更后，flow 文档 + skills/references + agent.md 必须同步更新，确保三处对同一动作的职责划分一致。

### 反例表
| 禁 | 改为 |
|---|---|
| flow 文档说「main 负责调用 skein check」，但代码已下沉给 skein-checker agent | flow 文档、agent.md、references 同步：谁负责谁来做，三处一致 |
| 改了 agent.md 加入新职责，忘更新 flow references | 改动前/后检查 flow/agent.md/references 三处是否协调 |
| subtask 快照在 flow 里，agent 需自读 — 文档还说「main 转抄」 | 文档改成「agent 自读」，去掉过时描述 |

### 适用场景
- 跨 agent/main 的职责调整
- dispatch prompt 变瘦（信息来源由 main 转给 agent）
- agent.md 新增自运行命令
