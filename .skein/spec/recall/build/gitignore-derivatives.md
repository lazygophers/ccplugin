## 衍生物清单单一登记处模式

### 触发场景
维护 `.gitignore` 或其他自动生成的文件清单时，需要追踪派生自真值源的衍生物。

### 陷阱-正解
**陷阱**：衍生物清单写死在 `.gitignore` 中，与其源头散落的写盘点无强制对应关系 → 必然漂移（新增衍生物却忘记登记）。
**正解**：建单一登记处（如 `DERIVATIVES` 字典），清单由它导出；配套机械守卫（文本扫描）发现「新增衍生物写盘点却未登记」就报红。

### 铁律
- MUST：衍生物清单由唯一真值源导出（如 config 或中央字典）
- MUST：新增衍生物写盘点时必须登记到中央源
- MUST：配套机械守卫接进 pytest，反向验证守卫确实会捕获漏注册

### 反例表
| 禁 | 改为 |
|---|---|
| `.gitignore` 写死衍生物清单 | 由 `DERIVATIVES` 等中央源导出 |
| 散落的模块各自写盘衍生物无登记 | 统一登记处，所有衍生物写盘前查表 |
| 守卫只验通过，不验失败 | 植入未登记项，确认变红；撤回 |

## 衍生物 vs 真值的判据

### 触发场景
判断某个文件是衍生物还是真值源时。

### 陷阱-正解
**陷阱**：凭文件名或位置猜。
**正解**：判据 = 「有没有一条命令能从真值重新产出它」。代价严重不对称：少忽略一个衍生物 = 仓库脏一点；多忽略一个真值 = 用户数据不进版本库。**拿不准一律判真值（不忽略）**。

### 铁律
- MUST：判据唯一标准 = 可否由真值源通过一条命令重产
- MUST：真值不被误忽略要逐条独立断言，不能只测一个代表
- MUST：拿不准时保守判真值，宁可多追踪

## 目录深度重叠陷阱

### 触发场景
新增 `.gitignore` pattern 时，要核实与真值文件目录结构的重叠。

### 陷阱-正解
**陷阱**：`spec/*/index.md` 只匹配单层，不误伤 `spec/<ns>/<cat>/<topic>.md` 正文。
**正解**：验证 pattern 作用域，确保不误伤预期保留的文件。

### 反例
| 禁 | 改为 |
|---|---|
| 目录 pattern 未考虑深度 | 逐层验证：`spec/*/` 不含 `<cat>/` 二级 |
| 新增 pattern 未测试副作用 | 植入样本真值，验证 pattern 不误伤 |

## 幂等三态是 gitignore 生成器改动的标准验证动作

### 触发场景
改动衍生物生成器或清单后的验收。

### 铁律
- MUST：新建工作区，验证生成器幂等产出
- MUST：条目齐全重跑零改动
- MUST：缺行重跑只补不覆盖用户手写条目

### 验收清单
1. [ ] 新建临时工作区，首次运行生成器 → 完整清单
2. [ ] 原工作区重跑生成器 → 零改动
3. [ ] 删除一行条目，重跑 → 补回删除行，保留用户手写条目
