# WS 重连指数退避 — PRD (主入口)

> 禁写具体文件路径与代码片段 (会很快过期) —— 例外: prototype 产出的能精确编码决策的片段 (状态机/schema/type shape) 可内联, 且须注明来自 prototype。

## 目标
要解决什么 / 用户价值 / 成功长什么样:
- [ ] 服务端长时间不可用时, 重连间隔逐次拉长而非恒定, 不再形成固定频率的请求风暴
- [ ] 服务端刚恢复的一瞬间, 多个标签页不同时打过去 (抖动错开)
- [ ] 短暂抖动 (服务重启) 下的恢复速度不比现状慢 —— 首次重试仍在 1 秒级

## 边界
范围内 / 范围外 (非目标) / 已知约束:
- [ ] 范围内: live WS 的重连调度策略 (间隔计算 + 尝试计数的重置时机)
- [ ] 范围外: 不改 WS 协议与消息类型; 不改「重连成功后整页重载补数据」的既有追赶方式; 不改断线横幅的提示时机
- [ ] 约束: **永不放弃重连** —— 现状注释已明确「服务端停多久都只挂横幅, 不自毁页面」, 退避只拉长间隔, 不设最大尝试次数
- [ ] 约束: 间隔必须有上限, 否则停机一夜后用户回来要等到天荒地老
- [ ] 约束: 前端是 Next.js 静态导出, 改完须重建 dist/

## User Stories
极其详尽地穷举, 覆盖功能各方面 (含边界情况) —— 穷举本身就是逼出边界情况的机械手段:
1. As a 用户, I want 服务重启时页面在一两秒内自己连回来, so that 我几乎察觉不到中断
2. As a 用户, I want 服务停了半小时期间浏览器不狂发请求, so that 不空耗电量与 CPU
3. As a 用户, I want 服务停了很久后恢复, 页面仍能在可接受的时间内连回来, so that 不用手动刷新
4. As a 用户 (多标签), I want 服务恢复时几个标签页错开重连, so that 不在同一毫秒砸向刚起来的服务端
5. As a 用户, I want 一次成功连接后再断开, 退避从头算起, so that 偶发断线不被之前的长间隔拖累
6. As a 用户 (边界), I want 连上后立刻又断 (半开连接/服务端起了又崩), 退避不被错误重置成永远的短间隔, so that 崩溃循环不退化成请求风暴
7. As a 用户, I want 断线横幅在首次转为断线时就出现, so that 我不会以为数据是新的 (现状行为, 不得回退)

## 验收标准
可执行、可核对的完成断言 (逐条):
- [ ] 重连间隔随连续失败次数递增, 不再是常量
- [ ] 间隔有明确上限, 且达到上限后保持在上限不再增长
- [ ] 首次重试的间隔不长于现状的 2 秒
- [ ] 间隔含随机抖动, 同一尝试次数下多次取值不完全相同
- [ ] 连接成功后失败计数归零, 下次断线从最短间隔重新开始
- [ ] 间隔计算是可独立调用的纯函数, 有单测覆盖
- [ ] 断线横幅的首次提示时机不变
- [ ] 前端构建零错, dist/ 已重建; 全量 pytest 不低于基线 410 passed / 0 failed

## 验证方式
每条验收标准的验证手段与通过标准 (plan 阶段必填):
- [ ] 递增与上限: 对间隔计算函数喂 0..N 次尝试, 断言序列单调不减且收敛到上限 —— 通过标准: 断言全绿
- [ ] 首次不退化: 断言尝试次数为 0 时的间隔上界 ≤ 2000ms —— 通过标准: 断言绿
- [ ] 抖动: 同一尝试次数多次取值, 断言取值集合不止一个且全部落在该次的合法区间内 —— 通过标准: 断言绿
- [ ] 计数重置: 读重连调度代码确认成功回调里重置计数, 并由测试覆盖「重置后回到最短间隔」 —— 通过标准: 断言绿
- [ ] 横幅时机: 对比改动前后的提示分支 —— 通过标准: 首次转断线即提示的条件未变
- [ ] 构建与回归: `npm run build` + `uv run pytest plugins/tools/skein/scripts/tests/` —— 通过标准: 构建零错, 410 passed / 0 failed

## Testing Decisions
什么算好测试 (只测外部行为不测实现细节) / 测哪些模块 / codebase 内的同类测试先例:
- [ ] 好测试 = 把间隔计算抽成纯函数后, 断言它的**数学性质** (单调、有上限、首值有界、抖动在区间内), 不断言「第 3 次必须正好是 4000ms」这类具体数值 —— 调参一次就红
- [ ] 抖动带随机性: 测「落在合法区间内」与「多次取值不全等」, 不测具体值; 需要确定性时由测试注入随机源, 不去 mock 全局 Math.random
- [ ] 不测: WebSocket 实例本身的生命周期、setTimeout 被调用了几次 —— 属实现细节, 且要造 WS mock, 成本远超收益
- [ ] 先例: `src/lib/__tests__/` 下 board-layout / depdag / priority-contrast 均为纯数据进纯断言出, 本次沿用
- [ ] 后端无改动, pytest 仅作回归护栏
