# task 优先级: 四档枚举 + 真正参与调度排序 — PRD (主入口)

> 禁写具体文件路径与代码片段 (会很快过期) —— 例外: prototype 产出的能精确编码决策的片段 (状态机/schema/type shape) 可内联, 且须注明来自 prototype。

## 目标
要解决什么 / 用户价值 / 成功长什么样:
- [ ] 建 task 时能指定优先级 —— 现状是字段存在但**命令行根本传不进去**, 所有 task 恒为默认值
- [ ] 优先级真正决定认领顺序 —— 现状是它被拓扑深度压过, 且执行中的 task 之间完全不看优先级, 「参与排队」名不副实
- [ ] 优先级从 0-10 数字改为四档 (紧急 / 高 / 中 / 低), 用的人不必自己维护一套数字约定
- [ ] 命令行与页面都能改优先级, 改完立刻影响后续调度

### 现状 (已核实, 非推测 —— 本 task 是补缺口不是从零建)
- [ ] 字段已存在: 0-10 整数, 默认 5, 已落盘在每个 task 上
- [ ] 列表读取已按 (状态, 优先级降序, id) 排序 —— 但这只影响就绪 task 的相对次序
- [ ] 认领的最终排序键是 (拓扑深度降序, task 登记序, subtask 登记序), **优先级不在其中**; 代码注释明写「执行中 task 同级, 不再分 task 优先级」
- [ ] 建 task 的命令没有优先级参数 —— 读取处有兜底默认值, 于是永远取默认
- [ ] 详情页已有优先级展示位, 但当前显示的是兜底值 (受另一处 raw 组装缺陷影响, 归 `dag-parent-nesting` 修)

## 边界
范围内 / 范围外 (非目标) / 已知约束:
- [ ] 范围内: 取值改四档并迁移存量、建 task 时指定、改优先级命令、认领排序纳入优先级、看板展示、页面直接改
- [ ] 范围外: subtask 级优先级 (本次只到 task 级)
- [ ] 范围外: 抢占式调度 (高优先级不打断已在跑的, 只影响下一次认领)
- [ ] 🔴 约束: **依赖硬优先** —— 依赖未满足的 task 再紧急也不能提前调度
- [ ] 🔴 约束 (用户裁定 2026-08-02): **优先级权重高于拓扑深度**。代价已知且接受 —— 关键路径优先这个既有优化会被冲淡, 总工期可能变长, 换取「标了紧急就真的先跑」
- [ ] 约束: 优先级是调度旋钮不是契约, 任意状态均可改
- [ ] 约束: 存量是 0-10 数字, 迁移到四档必须可逆且不丢信息 (须定义数字到档位的映射)
- [ ] 约束: 与 `concurrency-pools` 改同一处认领逻辑但层不同 (它改分池筛选, 本 task 改池内排序)。用户裁定并行推进, 后 merge 方解冲突, 解法不得破坏「依赖硬优先」与「同档稳定序」

## User Stories
极其详尽地穷举, 覆盖功能各方面 (含边界情况) —— 穷举本身就是逼出边界情况的机械手段:
1. As a 使用者, I want 建 task 时指定四档之一, so that 一开始就把轻重缓急记在盘上
2. As a 使用者, I want 不指定时默认「中」, so that 不关心优先级的场景零负担
3. As a 使用者, I want 认领时紧急的先被拿到, so that 标了紧急真的有用
4. As a 使用者, I want 依赖没满足的紧急任务不被提前拿走, so that 不会拿到半成品前置
5. As a 使用者, I want 执行中的多个 task 之间也按优先级排, so that 不是只有就绪 task 才享受优先级
6. As a 使用者, I want 同档内排序稳定可预期, so that 同样盘面每次结果一致
7. As a 使用者, I want 随时改优先级 (命令行), so that 情况变了调度跟着变
8. As a 使用者, I want 直接在页面上改优先级, so that 看着看板就能调度
9. As a 使用者, I want 页面改完立刻看到新值, so that 知道改动生效了
10. As a 使用者, I want 页面改失败时看到明确错误, so that 不会以为改成功了其实没改
11. As a 使用者, I want 改优先级不打断已在跑的, so that 不会有任务跑到一半被抢走
12. As a 使用者, I want 存量 task 的数字优先级被合理映射到四档, so that 升级后不丢已有的轻重区分
13. As a 使用者, I want 传非法档位时被拒绝并列出合法值, so that 不会静默落错值
14. As a 使用者, I want 看板卡片上看到优先级, so that 不点进详情就知道哪些在插队
15. As a 使用者, I want 全部同档时调度顺序与升级前一致, so that 不用优先级的人零感知

## 验收标准
可执行、可核对的完成断言 (逐条):

### 取值与迁移
- [ ] 优先级取值为四档: 紧急 / 高 / 中 / 低
- [ ] 存量 0-10 数字按明确定义的映射迁移到四档, 映射规则写在设计文档里
- [ ] 迁移可逆 (迁移前有快照或可回滚), 且迁移后 `doctor` 通过
- [ ] 未指定时为「中」
- [ ] 非法档位被拒, 错误信息列出四个合法值

### 命令
- [ ] 建 task 时可指定优先级 (当前根本传不进去, 这是最关键缺口)
- [ ] 提供改优先级命令, 任意状态的 task 都能改
- [ ] 单 task 查询与列表展示均可见优先级

### 调度排序 (本 task 的核心)
- [ ] 认领的排序键中**优先级权重高于拓扑深度**
- [ ] 执行中的多个 task 之间也按优先级排 (当前明确不分, 须改掉)
- [ ] 依赖未满足的 task 不因优先级高而被提前认领 (须有独立用例证明)
- [ ] 同档内排序稳定: 同一盘面重复认领结果一致
- [ ] 全部同档时认领顺序与本改动前一致 (零回归)
- [ ] 改优先级不影响已在跑的 subtask

### 展示与页面改动
- [ ] 看板卡片显示优先级
- [ ] task 详情显示优先级**真实值** (非兜底值)
- [ ] 页面上可直接改某 task 的优先级
- [ ] 页面改完后界面立刻反映新值, 无需手动刷新
- [ ] 页面改动失败时给出明确错误提示, 不静默失败
- [ ] 页面改优先级复用既有的白名单命令通道, 不新增专用写接口

### 兜底
- [ ] `python3 scripts/skein.py doctor` 通过 (含非法优先级值体检)
- [ ] 新增用例覆盖: 默认档 / 四档排序 / 优先级压过拓扑深度 / 依赖优先于优先级 / 执行中 task 间也排序 / 同档稳定序 / 非法值被拒 / 存量迁移映射 / 全同档零回归
- [ ] 页面改优先级经真实浏览器验证: 点击改档后**屏幕上真的变了** (非仅 DOM 变化)

## Testing Decisions
什么算好测试 (只测外部行为不测实现细节) / 测哪些模块 / codebase 内的同类测试先例:
- [ ] 排序接缝取**认领命令的返回顺序** —— 最高接缝, 是使用者真正观察到的外部行为, 不测内部排序函数
- [ ] 「优先级压过拓扑深度」必须有独立用例: 构造一个低拓扑深度但高优先级的 task, 断言它先被认领 —— 这条是本次改动的核心断言, 缺了等于没验
- [ ] 「依赖优先于优先级」独立用例: 高优先级但依赖未满足, 断言未被认领
- [ ] 「零回归」用例: 全部同档时认领顺序与改动前一致
- [ ] 存量迁移用例: 构造若干 0-10 数字的老 task.json, 断言迁移后档位符合映射表
- [ ] 页面改优先级不写脆弱的 UI 自动化断言, 列为浏览器人工核对项
