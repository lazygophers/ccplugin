# skein-flow 卫星文档并入 flow-loop — 详细设计

架构 / 数据流 / 关键取舍 / 技术选型 (不含调度图, 调度归 task.json):

## 为什么该合

三份卫星文档都只有 19–23 行, 且其中两份已经被 flow-loop 正文直接引用 —— 正文讲判据、卫星只放
一段模板, 切分点本就在「同一件事」的中间。读者拿一段报告模板要多跳一次文件, 收益为零。

第三份的情况不同: 它自称是某判据的**单一真值源**, 但只从 SKILL 索引与另一份 reference 被指到,
flow-loop 正文反而没引。真值源不在唯一真值源文件里, 这是本次要顺手纠正的结构问题。

## 承接位置 (四份 → 五处)

- 沉淀判定门 → finish 过程节。它讲的就是 finish 后异步跑什么, 归位即可。
- 根因复盘模板 → 根因复盘节。正文已有 5 维判据, 模板接在后面, 一节自足。
- 入口判据 (归一 vs 分立 / worktree 豁免) → **新增一节**放在参数路由之后、状态模型之前。
  这两项是「进不进 flow」的前置判断, 排在状态机之前才符合阅读顺序。
- 完成判定 → 终止条件节。「什么算完成」与「什么时候停」是一回事的两面, 合在一处才不会各说各话。
- 工时规则 → planning 工件文档的 subtask DAG 与 estimate 节。**注意这一份不并入 flow-loop** ——
  它服务的是「怎么写 planning 工件」, 与 for-plan 同主题; 塞进执行过程真值源反而错位。

## 关键取舍

- **只搬不改**: 判据口径一个字不动。合并的价值在减少跳转, 不在顺手优化措辞 —— 一旦开始改写,
  就无法用「与旧版本逐段比对」来证明零丢失, 验收也就没了抓手。
- **删掉的只有转述句**: 形如「细节见某文件」的句子在合并后自我指涉, 必须去掉; 这是唯一允许的删减。
- **不动 dag-scheduling**: 它有独立体量与独立主题 (拆分与调度), 本次不扩范围。
- **历史提及保持原样**: 归档 task 的 json 与设计文档里提到旧文件名, 那是当时的事实记录,
  改了等于篡改历史。grep 校验时须排除归档目录。
- **源码注释里的指路也要改**: 有 Python 注释以「规则详见某文件」指向被删文件, 属活引用不是历史记录,
  必须一并改指, 否则读代码的人扑空。

## 测试接缝 (seam)
check 阶段验证的是`行为对不对`而非`跑没跑起来`, 全靠这里选对接缝。三条规则:
1. 优先复用现有接缝, 不新建
2. 取最高接缝 (越靠外部行为越好)
3. 越少越好, 理想 = 1 个

**接缝 = 仓内既有的文档护栏 (全仓文档扫描类测试) + 与 git 旧版本的逐段比对**。

选它的理由: 纯文档搬迁没有可执行的行为面, 能证伪的只有两件事 —— 链接还通不通 (既有护栏管),
内容有没有丢 (与旧版本比对管)。不为一次性搬迁新建测试, 是「优先复用现有接缝」的直接应用。

不选的接缝: 给文档段落写文本断言 (段落会随后续正常编辑漂移, 写死即脆, 且会把文档变成不敢改的
冻结物)、只跑一次 AI 理解校验就下结论 (端点抖动会让单次结果不可信, 故要求同 prompt 连跑 3 次)。
