# skein-flow 卫星文档并入 flow-loop — PRD (主入口)

> 禁写具体文件路径与代码片段 (会很快过期) —— 例外: prototype 产出的能精确编码决策的片段 (状态机/schema/type shape) 可内联, 且须注明来自 prototype。

## 目标
要解决什么 / 用户价值 / 成功长什么样:
- [ ] 四份小卫星文档并回各自正文, 读者不再为拿一段模板多跳一次文件
- [ ] flow-loop 作为「执行过程唯一真值源」名副其实, 判据与模板同处一页
- [ ] 全仓引用同步改指, 零断链

## 边界
范围内 / 范围外 (非目标) / 已知约束:
- [ ] 范围内: 四份 reference 的内容搬迁与删除 (三份并入 flow-loop, 工时规则并入 planning 工件文档), 承接章节的整合, 以及全仓指向这四份文件的链接改指
- [ ] 范围外: 不动 dag-scheduling; 不改任何流程语义与判据口径; 不动 CLI 与测试代码
- [ ] 约束: **实质内容零丢失** —— 只搬位置、去掉「详见某文件」这类转述句, 不得借合并之机删减或改写判据
- [ ] 约束: 其中一份自称是某判据的「单一真值源」, 搬迁后该真值源地位须由承接章节继承, 不得出现两处并存的表述
- [ ] 约束: 按项目规范, skill 文档改动须过 AI 可理解性校验

## User Stories
极其详尽地穷举, 覆盖功能各方面 (含边界情况) —— 穷举本身就是逼出边界情况的机械手段:
1. As a 读 flow 文档的 agent, I want 根因复盘的判据与报告模板在同一节, so that 不用为拿模板再跳一个文件
2. As a 读 flow 文档的 agent, I want finish 阶段的沉淀判定门就写在 finish 节里, so that 读完该节即可执行
3. As a 读 flow 文档的 agent, I want 入口判定 (何时建 task / 归一还是分立 / 何时可 inline) 在 flow-loop 里有明确落点, so that 入口与执行同源
4. As a 读 flow 文档的 agent, I want 完成判定与终止条件同处一节, so that 「什么算完成」只有一个说法
5. As a 维护者, I want 删掉的文件在全仓再无引用, so that 不出现点开即 404 的链接
6. As a 维护者 (边界), I want 归档 task 里对旧文件名的历史提及保持原样, so that 历史记录不被改写
7. As a 维护者, I want 合并后 flow-loop 仍能被 AI 稳定读懂主流程, so that 文档合并不以牺牲可用性为代价

## 验收标准
可执行、可核对的完成断言 (逐条):
- [ ] 四个源文件已从 references 目录删除
- [ ] 四份文件的实质内容全部出现在各自承接章节, 逐段可核对, 零丢失
- [ ] 全仓 (排除 .skein 归档) 零处引用已删文件 —— 含源码注释里的文件名提及
- [ ] 改指后的链接锚点在 flow-loop 内真实存在
- [ ] 「单一真值源」声明只在承接章节出现一次, 无并存表述
- [ ] flow-loop / for-plan / SKILL 过 AI 可理解性校验, 同一 prompt 连跑 3 次主流程描述一致
- [ ] 全量 pytest 不低于基线 410 passed / 0 failed

## 验证方式
每条验收标准的验证手段与通过标准 (plan 阶段必填):
- [ ] 删除: 列目录 —— 通过标准: 四个文件名不在
- [ ] 零丢失: 用合并前的 git 版本与合并后的承接文件逐段比对 (每个源文件的每个小节都要在新位置找到落点) —— 通过标准: 逐条命中, 差异仅限转述句与标题层级
- [ ] 零引用: 全仓 grep 四个文件名, 排除 `.skein/task/archive` —— 通过标准: 零命中
- [ ] 锚点可达: 扫改动文件里的 md 链接, 逐条核对目标文件与锚点存在 —— 通过标准: 零断链
- [ ] 真值源唯一: grep 该声明短语 —— 通过标准: 仅一处
- [ ] AI 理解: 按项目规范用 `cat <文件> | claude -p --bare "<问题>" --output-format stream-json` 管道校验 —— 通过标准: 3 次返回非空且切题, 主流程描述一致
- [ ] 回归: `uv run pytest plugins/tools/skein/scripts/tests/` —— 通过标准: 410 passed / 0 failed

## Testing Decisions
什么算好测试 (只测外部行为不测实现细节) / 测哪些模块 / codebase 内的同类测试先例:
- [ ] 本任务是纯文档搬迁, 「好测试」= 复用仓内既有的文档护栏, 不为一次性搬迁新建测试
- [ ] 既有护栏: 仓内已有扫全仓文档 CLI 示例有效性的测试, 以及 spec 侧的断链检查 —— 合并后它们必须仍绿
- [ ] 内容零丢失靠与 git 旧版本逐段比对, 这是人/agent 的核对动作, 不写成断言 (段落文本会随后续编辑漂移, 写死即脆)
- [ ] AI 可理解性校验是项目 CLAUDE.md 对 skill/agent 文档改动的强制要求, 端点抖动 (空返回/跑题) 属重跑而非结论
- [ ] 后端无改动, pytest 仅作回归护栏
