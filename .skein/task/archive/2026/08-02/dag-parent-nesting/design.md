# DAG 父子容器包裹 + 详情展父子 — 详细设计

架构 / 数据流 / 关键取舍 / 技术选型 (不含调度图, 调度归 task.json):

## 布局: 组内布局 + 组作超节点 (两段式)

不改 Sugiyama/tiered 布局引擎本身, 在其外面包一层:

1. **分组**: 按 `parent` 把 task 切成若干组 (每个有 child 的父一组) + 一堆无父的独立 task。
2. **组内布局**: 每组的 child 集合单独跑一次现有布局函数, 得组内相对坐标与包围盒尺寸。
3. **外层布局**: 每组当成尺寸 = 包围盒 + padding 的**超节点**, 与独立 task 一起再跑一次现有布局函数。
4. **落位**: 组内相对坐标 + 超节点绝对坐标 = child 最终坐标; 容器框 = 超节点矩形。

跨组依赖用**排序提升**处理: child 的 deps 指向组外 task 时, 外层图上体现为「组 → 该 task」的顺序约束;
但**绘制**时边仍连回具体 child 卡片 (端点不上提), 只有排序上提。

取舍: 也可以改布局引擎让它原生懂分组, 但那要动已调优过的走线/边捆绑逻辑 (见 ADR 0001), 收益不抵风险。
两段式复用同一个函数, 组内组外行为天然一致。

**跨组成环** (A 组 child 依赖 B 组 child, B 组另一 child 又依赖 A 组): 容器**始终保留**, 成环的那条
回边只是不参与外层排序, 边照常绘制。代价是图上会出现从下往上的边 —— 接受, 因为包裹一致性优先于
「所有边都朝下」。禁用「检测到环就打散容器」的降级, 那会让同一份数据在不同筛选下时而有框时而没框。

**parent 与 deps 正交**: parent 表归属, deps 表执行顺序, 挂了 parent 不动任何既有 deps。组内 deps 边
照画, 跨组 deps 边照画。

## 边的处理

- 父子关系**不再生成边** —— 包裹本身就是这层语义的表达。
- deps 边全部保留, 端点始终是具体 task 卡片。
- 组内边、跨组边走同一套现有连线渲染, 不区分。

## 退化与零回归

- 组内 child 数为 0 → 不建容器, 该父按普通卡片参与外层布局。
- 全库无 `parent` → 分组结果全是独立 task, 外层布局等价于改动前的单次布局调用, 输出不变。
- 状态筛选发生在分组之前 (先过滤 task 集合再分组), 故筛掉部分 child 组自然收缩、筛空则组退化。

## 挂载命令

给既有 task 补/改 `parent`。校验复用 create 时那条 parent 链检查 (父存在 / 非自引用 / 父自身无 parent
即不超 2 层 / 不成环), 不另写一套。摘除 = parent 置空。

## 详情页

父子数据后端已提供 (parentTask / childTasks), 详情页只做展示与跳转; 详情页的依赖小 DAG 复用同一套
「父子不画边、改包裹」规则, 与看板保持一致。

**包裹的生效条件 (2026-08-02 check 阶段收窄)**: 小 DAG 只在**父节点本身落在图内**时才把它与其 child
成组画框 (`depdag.ts` 的 `visited.has(parentId)` 条件)。若图里只有同父的兄弟、父不在图中, **不画框**。

理由: 框代表的就是那个父; 父不在图里却画个框, 等于画了个无主容器, 比不画更误导。代价是「同父兄弟
在小 DAG 里看不出同属关系」—— 接受, 因为归属关系在详情页的「父子关系」区块已有明确表达, 小 DAG
的职责是依赖链而非归属。看板 DAG 不受此限 (它是全量图, 父必在图内)。

## 测试接缝 (seam)

- **布局接缝**: 布局函数的返回值 (节点集 + 容器集 + 边的端点 id)。最高接缝 —— 断言容器数量/child 归属/
  边端点/零父子时输出不变, 全部只看外部输出, 不碰内部分组中间态, 也不断言像素坐标。
- **挂载接缝**: CLI 命令的退出码与落盘后的 task.json `parent` 字段。沿用既有 lifecycle 测试写法。
- 渲染是否「屏幕可见」不做自动化断言 (快照测试脆且证明不了可见性), 靠浏览器截图人工核对。
