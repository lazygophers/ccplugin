# master 基线 19 条红回绿 — 详细设计

架构 / 数据流 / 关键取舍 / 技术选型 (不含调度图, 调度归 task.json):

## 测试接缝 (seam)

check 阶段验证的是`行为对不对`而非`跑没跑起来`, 全靠这里选对接缝。三条规则:

1. 优先复用现有接缝, 不新建
2. 取最高接缝 (越靠外部行为越好)
3. 越少越好, 理想 = 1 个

**本 task 三组各自沿用被修对象原有的接缝, 不新建任何接缝。**

这是刻意的: 本 task 的产出**就是**测试, 目标是让它们回到能跑的状态, 不是重新设计它们测什么。
换接缝会把「适配迁移」和「改变覆盖」混成一件事, 之后没人分得清哪条红是哪件事引起的。

| 组 | 接缝 | 迁移前后是否变 |
|---|---|---|
| A | 前端逻辑模块的导出函数 | **不变** —— 只换了实现语言, 导出契约照旧 |
| B | 命令行入口的参数与退出码 | 不变 |
| C | 既有两条守卫的断言 | 不变 (守卫零改动是硬验收) |

## A 组: TS 执行通道选型

被测的两个前端逻辑模块**零 import, 完全自包含** —— 这是本组能走最懒路线的关键前提,
它排除了路径别名解析、React 运行时、打包器这三类通常绕不开的麻烦。

| 方案 | 取舍 |
|---|---|
| **运行时原生类型擦除 (选)** | 零新依赖, 零构建步骤, 直接跑源文件。本仓 node 版本已默认支持, 实测可直接导入成功 |
| 引入 TS 执行器依赖 (tsx / ts-node) | 为已经能干的事装一个包。新克隆仓库多一步安装, 换来的能力是零 |
| 先编译再跑 | 引入构建步骤 = 引入「忘了重新构建」这个假绿口子, 正是用户裁定要避开的 |
| 引入前端测试框架 | 为 13 条断言拉进一整套工具链, 且用户已明确不另起炉灶 |

**已知坑 (实测撞到)**: 直接跑源文件时运行时会往 stderr 打一条模块类型未声明的告警。
测试若把 stderr 非空当失败, 会得到一条与被测逻辑无关的红。

处理方向是**在测试侧抑制该告警**, 而不是去改前端的包声明 —— 那个声明归前端构建管,
为了让 python 侧测试好跑而去动它, 是把成本推给了不相干的一方, 且可能影响构建产物。

**失败信息必须可分辨** (PRD user story 3): 执行通道自身失败 (模块找不到、语法不支持)
与被测逻辑断言失败, 要能一眼分开。前者的修法是修通道, 后者是修逻辑, 混在一起会白白浪费一轮排查。

## B 组: 为什么不只是加个参数

四条红的直接修法是给调用点补上新增的必填参数, 十分钟的事。但根因是
**改命令签名时靠人工找调用点, 找漏了一个文件** —— 同样的漏法下次还会发生。

本组仍按 PRD 只做补参数 (范围内是 19 条红), 但**必须做一次全仓搜索确认无第三处遗漏**
(PRD 验收标准第 6 条)。搜索本身就是这次的防线; 要不要上更硬的守卫留给后续 task 判断,
本 task 不扩范围。

## C 组: 修被守一侧, 守卫零改动

两条守卫报的红是**真违规**, 不是误报:

- 类型侧: 服务端入口新增了几个实例属性, 但没登记进类型声明块, 于是类型检查看不见它们。
  正解是补登记 —— 这正是上一轮刚立的规矩, 本组是它的第一次实战检验。
  **禁用压制注释绕过** (PRD 验收: `# type: ignore` 数量不增加)。
- 衍生物侧: 服务端入口写了一个未登记的产物文件。它确实是可重建产物, 正解是补进衍生物清单。

**「守卫红了就改守卫」是本 task 最大的失败模式。** 守卫的 git diff 必须为空 ——
这条写成硬验收就是为了堵死这个口子。守卫是上一轮花了力气反向验红建起来的,
第一次真抓到东西就把它改宽, 等于白建。

修完还要**再反向验红一次** (种入违规确认红, 再还原)。理由: 修被守一侧时有可能顺手把守卫
覆盖到的路径改没了 —— 守卫还在, 但已经守不着东西了, 表现和「修好了」一模一样。

## 串行化

三组文件不重叠 (A 改前端测试, B 改调度测试, C 改服务端入口与衍生物清单),
但**共用同一个 worktree**, 属共享环境 —— 并发写各自文件 + 各自提交会互相顶掉。故串行。

排序按「先降噪后攻坚」: 先做 B (最小, 四条), 再做 C (两条, 但涉及守卫需谨慎),
最后做 A (13 条, 需引入执行通道)。这样做 A 时基线只剩它自己的红, 干扰最小 ——
这与本 task 的整个立意 (干净基线才分得清红的来源) 是同一条道理, 在 task 内部也适用。

## 风险

- **执行通道的 node 版本依赖**: 原生类型擦除对运行时版本有下限要求。
  低于该版本的环境会整组失败。对策: 通道不可用时给出明确的版本要求提示 (PRD user story 9),
  而不是让人对着一堆模块解析错误猜。
- **迁移时被测行为悄悄变了**: 若换语言时顺手改了逻辑, 照搬旧断言会红, 而这条红是**真的**。
  对策: 遇到此类红**禁改断言让它绿**, 停下来回报 —— 那是迁移的缺陷, 不是测试的缺陷,
  归属另一会话, 按 PRD 边界属范围外。
