# 优先级 UI 主题适配 — PRD (主入口)

> 禁写具体文件路径与代码片段 (会很快过期) —— 例外: prototype 产出的能精确编码决策的片段 (状态机/schema/type shape) 可内联, 且须注明来自 prototype。

## 目标
要解决什么 / 用户价值 / 成功长什么样:
- [ ] 优先级标签在 light / dark 两套主题下都清晰可读 (对比度过 WCAG AA 4.5:1)
- [ ] 四档优先级 (紧急/高/中/低) 视觉上可区分四档, 不是三档
- [ ] 优先级色不再借用状态色 token, 各自有独立的、按主题分别取值的前景色变量

## 边界
范围内 / 范围外 (非目标) / 已知约束:
- [ ] 范围内: 优先级标签与优先级下拉选择器的呈现 (色值定义 + 消费点), light/dark 两套取值
- [ ] 范围外: 状态色体系本身不动 (状态徽章是白字铺底, 语义正确); 不引入第三套主题; 不改优先级机器值枚举与排序权重
- [ ] 约束: 色值必须落在 CSS 变量层按主题分别定义, 禁在组件里内联 hex; 已有 oc-* 调色板优先复用, 不新增色相
- [ ] 约束: 前端是 Next.js 静态导出, 改完必须重建 dist/ 否则线上看不到

## User Stories
极其详尽地穷举, 覆盖功能各方面 (含边界情况) —— 穷举本身就是逼出边界情况的机械手段:
1. As a 用户, I want 在 light 主题下看板卡片上的「高」优先级标签清晰可读, so that 不用凑近屏幕辨认
2. As a 用户, I want 在 dark 主题下同一标签同样清晰, so that 切主题不损失信息
3. As a 用户, I want 「中」和「低」两档能一眼区分, so that 四档枚举名副其实
4. As a 用户, I want 「紧急」在两套主题下都最醒目, so that 优先级有视觉梯度
5. As a 用户, I want 优先级下拉框展开时选项底色跟随主题, so that 不出现浅底黑字/深底黑字的错配
6. As a 用户, I want 任务详情页与看板卡片的优先级呈现一致, so that 同一概念不在两处长得不一样
7. As a 用户 (边界), I want 优先级字段缺失或取到未知值时回落到「中」且样式正常, so that 脏数据不炸版
8. As a 开发者, I want 优先级色与状态色在变量层就分家, so that 以后改状态色不会连带改坏优先级

## 验收标准
可执行、可核对的完成断言 (逐条):
- [ ] 四档优先级前景色在 light / dark 各自定义, 对比度均 ≥ 4.5:1 (以各自实际所处的卡片底色计)
- [ ] normal 与 low 使用不同色值, 四档两两可区分
- [ ] 优先级消费点不再引用 --st-* 状态色 token, 组件内无内联 hex
- [ ] 看板卡片与任务详情页两处优先级呈现一致
- [ ] dist/ 已重建且含新样式
- [ ] 前端既有测试全绿, 全量 pytest 不低于基线 410 passed / 0 failed

## 验证方式
每条验收标准的验证手段与通过标准 (plan 阶段必填):
- [ ] 对比度: 按 WCAG 相对亮度公式算四档 × 两主题共 8 组前景/背景对比度 —— 通过标准: 全部 ≥ 4.5
- [ ] 色值分家: grep 优先级色映射与其消费点 —— 通过标准: 零处引用 --st-*, 零处内联 hex (#RRGGBB)
- [ ] 四档可区分: 读四档色值定义 —— 通过标准: 四个值两两不等
- [ ] 两处一致: 对比看板与详情页的优先级渲染代码 —— 通过标准: 走同一映射与同一样式来源
- [ ] dist 重建: 构建后 grep 产物含新变量名 —— 通过标准: 命中
- [ ] 回归: `npm run build` 零错 + `uv run pytest plugins/tools/skein/scripts/tests/` —— 通过标准: 构建成功, 410 passed / 0 failed

## Testing Decisions
什么算好测试 (只测外部行为不测实现细节) / 测哪些模块 / codebase 内的同类测试先例:
- [ ] 好测试 = 断言「算出来的对比度达标」「四档色值互异」这类可计算的外部属性, 不断言具体 hex 是多少 (那是实现细节, 调色一次就红)
- [ ] 不测: React 渲染出的 DOM 结构、className 字符串拼接 —— 属实现细节
- [ ] 无浏览器不做视觉判定: 只以色值计算为准, 禁以「DOM 里有这个 class」推断「屏幕上看得清」
- [ ] 先例: `src/lib/__tests__/` 下既有 board-layout / depdag 等纯函数单测, 本次沿用同一形态 (纯数据进纯断言出)
- [ ] 后端侧无改动, pytest 仅作回归护栏
