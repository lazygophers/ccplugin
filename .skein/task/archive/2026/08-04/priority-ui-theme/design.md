# 优先级 UI 主题适配 — 详细设计

架构 / 数据流 / 关键取舍 / 技术选型 (不含调度图, 调度归 task.json):

## 根因

不是「忘了用 CSS 变量」, 是**用错了变量的语义**。

状态色 (`--st-*`) 是按**徽章底色**设计的 —— 白字铺在色块上, 所以 dark 主题取更深的 `-800` 档,
浅色主题取 `-600` 档, 这对底色是正确的。优先级标签却把同一批 token 拿来当**文字色和边框色**,
方向正好反过来: 前景色在 dark 下需要更亮, 在 light 下需要更暗。

实测对比度 (WCAG 相对亮度公式, 以标签实际所处的卡片底色计):

| 档 | light | dark | AA 4.5 |
|---|---|---|---|
| urgent | 2.51 | — | light 不过 |
| high | 2.23 | 3.65 | 双双不过 |

`--destructive` 本身是前景色 token (dark 取更亮的 400), 所以 urgent 只有 light 侧不达标;
`--st-check` 是彻底的底色 token, 两侧都不达标。

第二个缺陷: normal 与 low 映射到同一个变量, 四档枚举视觉上只呈现三档。

## 关键取舍

- **新开一组优先级专用前景色变量, 不复用状态色**: 根因就是两套语义混用。只调数值不分家的话,
  下次改状态色会再次连带改坏优先级 —— 这是 User Story 8 要的。
- **复用既有 oc-* 调色板, 不引新色相**: 四档需要的是同色系不同深浅 + 与状态色可区分, 调色板
  已有足够档位; 新增色相会让整套配色失控。
- **只改前景/边框色, 不给优先级标签铺底**: 铺底会和状态徽章抢视觉权重 —— 状态是主信息,
  优先级是辅信息, 现有的「描边小标签」形态是对的, 只是取色错了。
- **色值定义留在 CSS 变量层, 映射表只存变量名**: 组件与详情页共用同一映射, 天然满足「两处一致」,
  且换肤只需改变量。

## 测试接缝 (seam)
check 阶段验证的是`行为对不对`而非`跑没跑起来`, 全靠这里选对接缝。三条规则:
1. 优先复用现有接缝, 不新建
2. 取最高接缝 (越靠外部行为越好)
3. 越少越好, 理想 = 1 个

**接缝 = 色值定义 + 对比度计算的纯函数单测** (沿用 `src/lib/__tests__/` 既有形态)。

选它的理由: 无浏览器环境下, 「屏幕上看不看得清」唯一可证的形式就是算对比度; 色值是纯数据,
断言可计算、不脆。一个接缝同时覆盖「达标」「四档互异」「不引用状态色」三条验收。

不选的接缝: 截图/视觉回归 (无浏览器, 且按项目禁区规则 DOM 存在 ≠ 屏幕可见, 不可作放行依据)、
React 组件渲染断言 (测的是 className 拼接这类实现细节, 调样式就红)。
