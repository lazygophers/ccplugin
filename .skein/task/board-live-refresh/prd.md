# 看板实时刷新: task-changed 消息未被消费 — PRD (主入口)

> 禁写具体文件路径与代码片段 (会很快过期) —— 例外: prototype 产出的能精确编码决策的片段 (状态机/schema/type shape) 可内联, 且须注明来自 prototype。

## 目标
要解决什么 / 用户价值 / 成功长什么样:
- [ ] 人停在看板上时, task 的创建/变更/完成能自动反映到界面上, 不必手动刷新
- [ ] 更新是**局部软刷** —— 只换掉变化的那张卡片, 不整页重载, 不打断正在进行的操作与滚动位置
- [ ] 修的是真根因: 后端已逐 task 推送变更消息, 前端把这类消息整个丢掉了 —— 不是缺机制, 是消息没人接

## 边界
范围内 / 范围外 (非目标) / 已知约束:
- [ ] 范围内: 前端消费逐 task 变更消息做局部更新、变更签名字段覆盖不全的补齐、各页面订阅接线
- [ ] 范围内: 新建 task 与删除/归档 task 在看板上的即时增删 (不只是既有卡片的字段变化)
- [ ] 范围外: 推送机制本身重做 (轮询改事件驱动等) —— 现有机制够用, 问题在消费端
- [ ] 范围外: spec 页面的实时刷新 (走另一条消息, 不在本次)
- [ ] 约束: 整页重载的兜底路径要保留 —— 局部软刷覆盖不到的变化 (如构建产物更新) 仍需整页刷
- [ ] 约束: 变更签名扩字段会增加比对开销, 需权衡覆盖度与 CPU, 不能为了全覆盖把整个数据结构深比一遍

## User Stories
极其详尽地穷举, 覆盖功能各方面 (含边界情况) —— 穷举本身就是逼出边界情况的机械手段:
1. As a 使用者, I want 我开着看板时新建的 task 自动出现在图上, so that 不用记得手动刷新
2. As a 使用者, I want task 状态推进 (就绪→进行中→检查中→完成) 时卡片自动变色变进度, so that 看板真的是实时的
3. As a 使用者, I want task 被归档/删除时卡片自动消失, so that 看板不残留幽灵卡片
4. As a 使用者, I want 更新时页面不整体重载, so that 我的滚动位置、展开的详情面板、筛选条件都不丢
5. As a 使用者, I want 改 task 名称/描述这类字段也能触发更新, so that 不会出现「改了但看板还是旧名字」
6. As a 使用者, I want 详情页开着某个 task 时, 该 task 的变化能刷到详情页上, so that 详情页与看板一致
7. As a 使用者, I want 连接断开时有明确提示而不是静默失效, so that 我不会对着一个假的实时界面做判断
8. As a 使用者, I want 连接恢复后界面自动追上最新状态, so that 断线期间错过的变更不会永久丢失
9. As a 使用者, I want 短时间内大量 task 变更时界面不卡死, so that 批量调度时看板仍可用

## 验收标准
可执行、可核对的完成断言 (逐条):

### 消费与局部更新
- [ ] 逐 task 变更消息被前端消费, 不再被丢弃
- [ ] 收到变更消息时只更新对应卡片, **不触发整页重载**
- [ ] 新建 task 时卡片自动出现在看板上
- [ ] task 归档/删除时卡片自动消失
- [ ] 状态推进时卡片的状态色与进度同步更新
- [ ] 更新后滚动位置、已展开的面板、筛选条件均保持不变
- [ ] 详情页开着某 task 时, 该 task 的变化刷到详情页

### 变更覆盖
- [ ] 变更签名覆盖到会影响展示的字段 (至少含名称与展示所需的其余关键字段), 改名后看板能更新
- [ ] 签名字段的选取有明确取舍说明 (覆盖度 vs 比对开销), 不做整结构深比

### 健壮性
- [ ] 连接断开时界面有明确提示, 非静默失效
- [ ] 连接恢复后界面追上最新状态, 断线期间的变更不永久丢失
- [ ] 短时间内大量变更时界面不卡死 (批量调度场景可用)
- [ ] 整页重载的兜底路径保留, 局部软刷覆盖不到的变化仍能刷新

### 兜底
- [ ] 新增用例覆盖: 消息被消费 / 新建出现 / 删除消失 / 改名更新 / 局部不整页刷
- [ ] 经真实浏览器验证: 一边开着看板, 一边在另一侧改 task, 截图确认界面**在屏幕上真的变了** (非仅 DOM 变化)

## Testing Decisions
什么算好测试 (只测外部行为不测实现细节) / 测哪些模块 / codebase 内的同类测试先例:
- [ ] 消息消费逻辑取**输入消息 → 输出状态变化**这个接缝: 喂一条变更消息进去, 断言卡片集合的变化。纯函数可测, 不需要起浏览器
- [ ] 「不整页重载」这条用测试很难断言可靠 (重载行为在测试环境里本就不发生), 因此列为**浏览器人工核对项**, 不写脆弱的自动化断言
- [ ] 变更签名的覆盖度按「改某字段 → 是否产生变更消息」来测, 不测签名函数内部结构
- [ ] 断线重连按既有前端测试写法 (免框架 assert + tsc 编译后跑), 不引入测试框架
