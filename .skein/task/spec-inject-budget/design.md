# spec 注入总预算 800 token 口径统一 — 详细设计

架构 / 数据流 / 关键取舍 / 技术选型 (不含调度图, 调度归 task.json):

## 测试接缝 (seam)

check 阶段验证的是`行为对不对`而非`跑没跑起来`, 全靠这里选对接缝。三条规则:
1. 优先复用现有接缝, 不新建
2. 取最高接缝 (越靠外部行为越好)
3. 越少越好, 理想 = 1 个

**接缝 = 三个注入命令的输出文本。** 喂真实 spec 库, 取各命令输出, 断言其 token 估算值 ≤ 预算。

这是最高接缝: 它就是模型实际收到的东西。往下钻 (测某个页怎么被筛、怎么被拼) 是实现细节,
而「哪些页入选」正是本 task 要改的部分, 测它等于把改动钉死。

复用性: 仓库已有对注入文案做篇幅断言的先例 (判定文案篇幅守卫), 本 task 是同一手法换个对象。

## 三个注入点与预算归属

| 注入点 | 性质 | 实测 (字符) | 现状 |
|---|---|---|---|
| 会话常驻索引 | **每轮都付费** | 2363 | 三者之和约 38000 字符 |
| subagent 启动全文 | 每个 subagent 一次 | 20652 | ↑ |
| 显式取全文 | 人工按需 | 15301 | ↑ |

**口径 (用户 2026-08-01 裁定): 三点之和 ≤800 token。**

按中文约 1 字符/token 粗估, 现状之和约 38000 token 量级 —— 需要压掉约 98%。
**这不是压缩表达能达成的量级, 必然要求「常驻只留索引 + 全文改按需检索」的结构性取舍。**
这条结论要在 b4 (压到预算) 实做前先在 b1/b2 阶段用实测数据确认, 而不是做到一半才发现。

设计仍做成「注入点 → 预算」的单一数据表 + 一个总和约束, 理由不变: 口径若再变只改数值。
新增注入点必须在表里登记才能拿到预算 —— 拿不到就报错, 而不是默认无限 (PRD user story 8)。

**若实测确认 800 内无法保留可照做的规则, 按 PRD 约定回报用户重定口径, 禁自行放宽或硬压到失效。**

## 计量: 为什么不用真分词器

| 方案 | 取舍 |
|---|---|
| **字符数 × 标定系数** | 零依赖、hook 热路径无开销; 是估算, 有误差 |
| 引入 tiktoken | 它是 OpenAI 分词器, 对 Claude **同样是近似** —— 付了依赖和 import 开销却买不到精度 |
| 调 API 精确计数 | hook 热路径联网, 每轮对话一次网络往返, 不可接受; 且本轮实测该通道会长时间不可用 |

**取字符数 × 标定系数。** 关键在于系数不能拍脑袋: 中文约 1–1.5 字符/token, 英文和代码约 4,
而 spec 库是中英混排 + 代码片段, 差异能到四倍 —— 一个拍出来的系数在不同页上宽严完全不同。

**系数必须按本库真实内容标定, 且标定过程留在测试里可复算。** 这是本 task 唯一的估算环节,
也是最容易变成下一个「没人敢动的魔法数字」的地方 —— 仓库刚在另一个 task 上踩过「注释里写死的
数字会漂移失真」的坑, 同样的坑不踩第二次: 系数的来历固定在测试里, 后来人改它必须同时面对证据。

保守方向: 系数取偏高一侧 (即倾向高估 token 数)。低估会让实际开销悄悄超过用户要的 800,
高估只是让守卫更严 —— 误判代价不对称, 往严的一侧取。

## 压到 800 的手段

**压缩表达 + 降级低价值页, 不截断。** 截断会把规则从中间切断, 得到一份读起来完整、实际缺胳膊少腿
的注入 —— 那比超预算更危险, 因为它不可见。

压不进去时**报错并给出可执行信息**: 还差多少 + 最大的几页是谁 (PRD user story 9)。
让人知道该砍谁, 而不是丢一句「超了」。

降级挑选依据是价值密度而非单纯大小 —— 每轮都用得上的规则留在常驻, 偶尔才用的降为按需加载。

## 语义不丢怎么保证

现有测试已逐条钉住不能丢的规则, 压缩后必须原样绿, **禁靠放宽断言换绿**。

另有 AI 复读验法 (同一 prompt 连跑 3 次描述一致, 并与压缩前对照)。
**注意该验法依赖外部命令通道, 本轮该通道曾长时间不可用** —— 届时若仍不可用,
如实标记为未验证, **禁以推断代替**。

## 风险

- 系数标定不准 → 实际 token 超过 800 而守卫显绿。对策: 系数往高估一侧取 + 中英文页分别验证。
- 为压进预算而砍掉真正重要的规则 → 省了 token 但 AI 不照做了, 得不偿失。
  对策: 既有语义断言是硬底线, 压缩只能改表达不能删规则。
