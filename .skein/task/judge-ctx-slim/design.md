# 精简 judge _CTX 注入文案 — 详细设计

架构 / 数据流 / 关键取舍 / 技术选型 (不含调度图, 调度归 task.json):

## 1. 冗余从哪来 — 三类, 处置各不相同

压缩不是逐句砍字, 是按冗余类型下刀。已识别三类:

| 类型 | 表现 | 处置 |
|---|---|---|
| **自我论证** | 规则后面跟一整段「为什么要有这条规则」 | 砍到一句, 或整段删 —— 读者是 AI, 不需要被说服 |
| **跨段重复** | 同一条要求在规则段、论证段、前缀规则段各说一遍 | 留一处, 其余删。留在**最靠近执行时刻**的那处 |
| **与脚本证据串重复** | 文案里解释的事, 脚本注入的证据串里已经原样说了一遍 | 删文案那份 —— 证据串是随轮动态注入的, 更贴当轮 |

第三类最容易被忽略: 文案是静态的, 证据串是每轮按命中信号动态拼的。同一句话静态写一遍、动态再拼
一遍, 不但费 token, 还会让 AI 以为这是两条不同的指示。

**取舍: 论证段整体让位**。原文案里有相当篇幅在论证「为什么判定要写出来」「为什么原因不能写成结论
复述」。这些论证的正确读者是**改这份文案的人**, 不是每轮读它的 AI。它们该活在测试的 docstring 里
(那里已经有了) 和设计文档里, 不该每轮注入一次。

## 2. 硬约束: 被测试钉住的语义一条不丢

一批语义已被逐条断言钉死。压缩时它们是**不可协商的下限**, 且不允许通过放宽断言来换绿 —— 那是把
守卫拆了去迎合改动, 顺序完全反了。

若压缩过程中发现某条语义确实**该删而非该压**, 走法是: 连同它的断言一起删, 并在提交里写明理由。
留一个永远为真的空断言比没有断言更糟 —— 它看起来还在守着。

**上一轮手改造成的红断言**: 手改删掉了一条被钉住的示例。两条合法出路 —— 补回该语义, 或论证它
不该被钉住并删掉断言。**必须显式二选一并留下记录**, 不允许悄悄改断言让它变绿。

## 3. 篇幅守卫: 这次膨胀的根因对策

超预算之所以没被发现, 是因为**没有任何机制在看**。源码注释里写着一个数字, 但注释不会失败。

**取舍: 用机械长度断言, 不用「读起来是否啰嗦」这类判断**。篇幅是少数能机械判定的质量维度, 而
机械判定的价值恰恰在于它不依赖人有没有注意到。

阈值取压缩后实际值加少量余量。余量留太大等于没守 (下次膨胀到阈值内也没人管), 留太小则每次微调
文案都要改阈值。取值应当让「正常措辞调整」不触发, 而「新增一整段」触发。

**守卫必须反向验证**: 临时把文案撑爆, 确认真的变红, 再改回。没红过的守卫等于没有。这是本仓库
既有纪律, 不是本 task 新立的。

**注释、阈值、实际三者对齐**: 注释里那个数字这次要么删掉 (避免二次失真), 要么写成指向守卫的引用。
让同一个事实有两处独立记录, 正是它这次失真的原因。

## 4. 语义不变怎么证

断言只能证明关键词还在, 证不了「AI 读完行为一样」。

**取舍: 对照验证, 不只自比**。沿用仓库对提示词类文件的既定验法 (同一 prompt 连跑 3 次描述一致),
但必须**同时与压缩前的描述做对照** —— 三次一致地读错也叫一致, 自比通过说明不了压缩没伤到语义。

具体做法: 压缩前先跑一轮记下主流程描述, 压缩后再跑三轮, 三轮之间一致且与压缩前等价, 才算过。

## 5. 不做的事

- **不动信号检测逻辑**: 词表、正则、短句阈值都不碰。它们与文案篇幅无关, 混在一起改会让「行为变了
  是文案的锅还是词表的锅」无从分辨。
- **不动判定语义**: 只改表达。这是本 task 与「重新设计判定规则」的分界线, 越过去就是另一件事。
- **不管插件缓存滞后**: 注入实际生效的是插件市场缓存里的副本, 与仓库文件不同步。那是分发链路问题,
  和本 task 的文案编辑正交, 混进来会让验收标准无从判定 (改了但没生效算不算做完?)。

## 6. 已知风险

- **压缩误伤语义**: 最大风险。对策是 §2 的断言下限 + §4 的对照验证, 两道都要过。
- **阈值定得太松**: 守卫形同虚设。对策见 §3, 并要求反向验证时能看清它确实卡在预期位置。
- **转义字符**: 曾踩过反引号转义漏出反斜杠、注入后成怪字符串。已有断言覆盖, 重写时留意即可。

## 测试接缝 (seam)

check 阶段验证的是`行为对不对`而非`跑没跑起来`, 全靠这里选对接缝。三条规则:
1. 优先复用现有接缝, 不新建
2. 取最高接缝 (越靠外部行为越好)
3. 越少越好, 理想 = 1 个

**接缝 = 文案常量本身的文本断言** (该文件既有测试的做法, 复用不新建)。

理由: 这份文案是纯数据, 没有行为可言 —— 它的「外部行为」就是被注入的那段文本。在文本层断言既是
最高接缝也是唯一接缝: 再往外一层 (真起 hook 子进程) 只能验证它被注入了, 验证不了内容对不对, 而
内容对不对才是本 task 的全部。

篇幅守卫落在**同一个接缝**上, 不新开 —— 它只是同一段文本的另一条断言。

**不新建接缝**: 不起子进程验注入、不验插件缓存里的副本 (见 §5)。语义不变靠 §4 的 AI 对照验证,
那是人工验收项不是自动化测试, 写进验收标准而不伪装成断言。
