# 结构化根因复盘协议

check 反复失败后的执行路由统一见 [flow-loop.md §9](flow-loop.md#9-失败扭转)。本文件只保留根因定位方法和报告格式。

## 触发

同一问题定点修复多轮仍失败，且继续盲修会扩大风险时，main 停止堆 subtask，做 5 维根因定位。

## 5 维度探针

逐维度给证据；不要只查实现层。

1. 需求理解偏差：验收标准、契约、用户意图是否理解错。
2. 方案设计缺陷：design 是否本身走不通或有结构漏洞。
3. 实现 bug：需求与方案正确，代码逻辑、边界、拼写、调用点错。
4. 环境或依赖：版本、依赖、缓存、平台、worktree 状态导致失败。
5. 测试本身错误：断言、fixture、mock、初始化、旧用例错误。

多维命中时取最外层：需求错优先于方案错，方案错优先于实现错。

## 报告格式

```md
## 根因复盘

- 失败摘要：<最短可复现症状>
- 已尝试修复：<轮次 + 结果>
- 维度证据：
  - 需求理解偏差：<证据或排除理由>
  - 方案设计缺陷：<证据或排除理由>
  - 实现 bug：<证据或排除理由>
  - 环境或依赖：<证据或排除理由>
  - 测试本身错误：<证据或排除理由>
- root cause：<维度 + 一句话根因>
- 本次修：<定向修复建议>
- 同类防：<可复用契约；无则写无>
- 建议出口：<回 exec / 用户裁定回 planning / 新建 task>
```

## 沉淀

根因教训不自动写流水账。若可写成可验证契约，复用 `skein-spec sediment`；一次性问题跳过。
