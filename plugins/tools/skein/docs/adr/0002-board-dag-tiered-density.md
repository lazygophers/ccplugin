# ADR 0002 · 看板 DAG 回到真分层 (行 = 依赖深度)，靠两档节点尺寸换回来

- 状态: Accepted (2026-07-28)
- 取代: ADR 0001 (满铺网格 / 贴合装箱) —— 该 ADR 转为 Superseded
- 影响面: `assets/webapp/src/new/pages/board.js` 主看板 DAG 视图、`assets/webapp/src/design.css`

## 背景 (Context)

ADR 0001 判「行 = 依赖层」死刑，理由是实测 98 task 排出 **1120×15514px** 的细长柱子。但那个数字的构成是 **66 个占用行 × 220px 行高**。行高不是分层算法产生的，是**卡片尺寸**产生的 —— ADR 0001 把「卡片不允许缩小」当成不可动的约束，于是只剩「拆掉分层规则」一条路，改走满铺网格再改贴合装箱。

代价一直挂着：同一行不再等于同一依赖深度，方向只能靠箭头和边语义色认。用户在此后多轮反馈中始终说「依旧不是最优解」，并明确判据：「卡片在哪，是基于它的前置后置分别在哪决定的，最协调的位置」。

这一轮换了做法：不再用文字讨论，直接把 9 个方案在真实数据 (96 节点 / 159 边 / 宽 1400) 上渲染成图让用户选 (原型与 9 张对比图见 commit `2617d61cf` 的 `.scratch/dag-preview/`，已从工作区清出)。实测：

| 方案 | 画布 | 边总长 | 均边长 | 交叉 | 回绕 |
|---|---|---|---|---|---|
| A 贴合装箱 (ADR 0001 线上态) | 1262×3790 | 114098 | 713 | 348 | 58 |
| B 横向分层 | 11770×756 | 259598 | 1622 | 1469 | 0 |
| C 卡片缩到 150×64 (仍装箱) | 1334×1384 | 56288 | 352 | 141 | 49 |
| D 焦点邻域 + 折叠 | 1400×2008 | 37400 | 706 | 16 | 31 |
| **F 迷你 120×32 + 真分层** | 1068×2090 | 58215 | 364 | 563 | **0** |
| **G 中号 190×52 + 真分层** | 1243×2850 | 82740 | 517 | 563 | **0** |
| H 迷你 + 报纸分栏 | 1376×854 | 52554 | 328 | 265 | 10 |
| I 中号 + 报纸分栏 | 1402×1442 | 76715 | 479 | 242 | 19 |

关键读数: **F 比 A 还矮** (2090 vs 3790)，且回绕从 58 归零。分层排布从来不是问题，340×220 的大信息卡才是。ADR 0001 结论里那句「未来若要回退分层: 需先解掉宽度硬约束或卡片尺寸约束之一」是对的 —— 本轮解掉的正是卡片尺寸。

## 决策 (Decision)

**主看板改回真分层 `layoutTiered`，卡片尺寸做成两档。**

- **层号** = 最长路径深度 (Kahn 拓扑序推进; 环上节点入度永不归零，按原序补进 `topo` 保证全量绘制)
- **层内顺序** = barycenter (前驱平均 x)，跑两遍让第二遍拿到真实前驱坐标
- **层内折行**: 一行放不下就折成多行 (整层仍是同一依赖深度的相邻几行)，行数按 `perRow` 均分，避免末行只剩 1 个
- **层内居中** + 宽度硬约束 (`x` 不小于 `padX`，画布永不横向溢出)
- **两档密度**: `compact 190×52` (标题 + id/子任务进度两行) / `mini 120×32` (色点 + 标题一行)，详情两档都在 hover popover 里
- **默认档由画布算**: 先按 compact 排，高度 > `max(600, 视口高) × 3` 才降 mini (`autoDensity`)。刻意不用「> N 个任务用 mini」的节点数阈值 —— 图窄或任务少时 compact 本来就装得下，不该被一刀切缩小
- **手动切换**: 工具栏两枚按钮，选择存 `localStorage['skein.dag.density']`，再点一次回自动档

子任务迷你 DAG (`layoutSubDAG`) 不变，仍走 `layoutPacked` 分层装箱。

随之删除的死代码: `layoutCoord` (贴合装箱 + skyline)、`layoutGrid` (满铺网格 + 蛇形行序)、`cardHeight` (行高自适应)、`DAG_SIZES`。`bundleTrunks` / `edgeKinds` / `focusActive` / `nodePopover` 保留。

## 结果 (Consequences)

线上实测 98 task (视口宽 1880):

- compact: **1785×2326px**，回绕 0
- mini: 一屏内可见到 m6 层，回绕 0
- 「同一行 = 同一依赖深度」恢复 —— ADR 0001 明确记为代价的那条，现在拿回来了

**代价**: 卡面信息从「标题 + 描述 + 子任务进度条 + 状态色条」缩到「标题 + id/进度」(compact) 或「色点 + 标题」(mini)。描述、状态、完整子任务列表移到 hover popover 与详情面板。用户在 AskUserQuestion 中直接选定这个取舍 (F+G 两档可切换)。

**没选报纸分栏 (H/I)**: 面积最省 (854px)，但栏与栏之间要从上一栏底接到下一栏顶，回绕重新出现 (10/19)，且「一行 = 一个深度」只在栏内成立。用户选 F+G。

**状态色改走描边**: 32px 高的卡切一条 4px 顶部色带就只剩 28px 放字，故 `.dag-node.st-*` 用 `border-color` + 一枚 7px 色点。
