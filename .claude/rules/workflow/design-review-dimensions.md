# 设计类方案评审：维度清单随方案落盘，必含「默认尺寸与信息密度」

设计/方案类 workflow（多 agent 产出方案并评审拍板）定稿时，评审维度清单必须
写进方案.md 或决策文件——只活在 workflow prompt 里的维度，session 结束即蒸发，
复盘时无据可查（2026-10-26 retro 为核对此事全仓 grep 零命中，被迫考古推断）。

清单至少含四维：改动量、默认尺寸与信息密度、可验证性、一致性。**「默认尺寸
与信息密度」最容易漏**：评审 agent 系统性偏简洁，会拿改动量压信息呈现量——
表现为保守取值（弹窗 860px 上限、附件纯文本平铺、「目录名 · N 文件」不展开），
用户第一眼即翻案。评审推荐在信息呈现量上被用户推翻时，先核对这条维度是否
在清单里，再下「用户口味」结论。

出处：2026-10-26 进度页弹窗 session——同日 3 条评审推荐被用户翻案且同方向
（.scratch/memory/2026-10-26.md L6/L7/L57），评审维度清单无任何持久文件记载。
