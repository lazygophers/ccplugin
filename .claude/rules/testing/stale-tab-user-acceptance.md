# 用户报「还是旧行为」或「打不开」先怀疑旧标签：验收指令要明说关旧标签重开

「HTML 产物重生成后交用户肉眼验收」的隐含前提：用户看的是重生成后打开的页面。
浏览器不监视磁盘文件，重生成前打开的标签停在旧 JS——机制被探针证明正常、代码
零问题时，用户仍报「还是旧行为」（2026-10-26 linky 预览二返排查轮：逐条排除
拦截器 / 文件时序 / 浏览器缓存后，根因是用户点开的是重生成前的旧标签，零代码
改动）。

固定动作两处：

1. 交用户验收时明确说「关掉旧标签，重新打开新生成的文件」，不默认用户开的是新版
2. 用户报的现象与已验证机制矛盾时，先问「你看的页面是重生成前还是重生成后打开
   的」，再回头调试机制——一轮排查探针的成本远高于一句话确认

与副本漂移（项目 CLAUDE.md 的 diff -rq）方向相反：那个是磁盘文件比装出去的旧，
这个是用户看的页面比磁盘文件旧。

「打不开」是同一根因的另一种症状：agent 起的 localhost 服务页面（ask-me 表单等）
在服务停掉后，旧标签还留着，用户点它就是打不开——服务端代码零问题，全链路复现
也复现不出。报「打不开」先核对「你点的标签是不是上一张表单/上一次起的页面」，
别急着派代理复现。

出处：2026-10-26 linky 预览二返排查 session（headless Chrome 探针证明机制正常，
根因 = 旧标签）；2026-11-06 ask-me 修复轮复发同型——用户报「预览/新标签打不开」，
代理全链路复现不出，根因是用户点旧标签（旧表单服务已停），零代码改动。
