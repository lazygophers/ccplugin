# Fix 阶段会隐式扩大授权边界：停点要原样抄进 fix 派单

多阶段 workflow 里，实施 agent 遇到预案外改动会停下写回报待拍板；但后续 Fix
阶段的 agent 收到「审计打回项」后，会把同一个停点当普通待修项直接改掉——授权
边界被 fix 阶段隐式扩大，事后只能靠「当初授权范围恰好覆盖」兜底，范围窄一点
就是越权改动。

- fix / fixer 派单必须原样抄入实施阶段的授权边界与停点清单：「以下情况停下来
  回报，不自行决定：…」。「审计打回」只授权修被打回的那一项，不是重新拍板
  打回项周边的契约。
- 主对话验收时核对：fix 实际改动的文件与行为 ⊆ 原授权 ∪ 打回项。超出即打回
  重做，不因结果正确而追认。

出处：2026-10-24 ask-me token 优化 session：实施 agent 停下待拍板的
test-cli.mts 断言改动，由 Fix 阶段 agent 在审计打回后直接完成
（.scratch/memory/2026-10-24.md 第 2 条决策）。
