# 派单里的验收预期串不写死数字：当场取数或写取数命令

给核查/验收 agent 的派单里写「已完成 3/未建票 4/75%」这类预期串时，数字来自更早的快照。
被核查对象若是 live 数据（用户在用的 session 文件、正在追加的日志、活库），两次取数之间
文件会被追加，预期串过期，agent 拿过期串对照现场数据，白查一轮再得出「对不上」的误报。

固定动作（派单前二选一）：

1. **派单前最后一次取数**：数字在派单 prompt 里当场重取（不是抄上一轮 agent 的回报），
   并注明取数时间。
2. **写取数命令不写数字**：直接把「怎么算」写进派单（如「`grep -c '^- \[' <文件>`，
   `[x]` 计已完成、`[ ]` 计未建票，汇总=前者÷后者」），让 agent 自己取数，预期只写
   「两边一致」或「口径正确」这类不依赖快照的判据。

判据规则：凡「预期值会随时间漂移」的数据（文件行数、计数、百分比、mtime），派单里只写
口径和取数命令，不写死数值。

出处：2026-11-10 tracking-progress report/session 核查 session——首轮核查 agent 回报的
「已完成 3/未建票 4/75%」是当时的快照（hotarubi session 文件 4 行 checklist），用户随后
在 live session 文件里追加到 6 行，真值变 4/6/67%；过期预期串进了后续派单，agent 白查
一轮（.scratch/memory/2026-11-10.md 第 3 条决策「3/4/75% 是旧快照」）。同 session 佐证：
首轮「session/ 只有 1 个文件」的核查结论在数小时后同样过期——核查结论自带取数时刻，跨轮
引用时一律重新取数。
